# CLAUDE.md — zenetlabs/website

Commit with /commit. Plan with plan-well. One PR per plan.

Every PR gets exactly one review pass, owned by the /commit gate: one `reviewer` run over the whole diff vs main, plus `/code-review high` only when the diff is `high`. Always pass the level explicitly. Levels: `low` = docs/copy/config, no logic; `medium` = routine UI with no form/server/external-API surface; `high` = anything touching the server entry, redirects, the lead endpoint, D1, the cron outbox, Access, Turnstile or Resend. Never re-review after a fix round.

Decisions go through AskUserQuestion (recommended option first).

## Rules (cite by name)
- Few comments — docs live in ~/vault/projects/zenetlabs-website/.
- Never use `any`; type guards, no casts; never suppress a quality tool.
- No IIFEs; no useEffect to sync state; direct imports only (no barrels).
- Tests always (Vitest + Playwright/axe); keep existing tests updated.
- Never commit or push without explicit instruction in the same turn. No `stash`, `reset --hard`, `checkout .`, `clean`.

## Stack facts
- TanStack Start SSR (no prerender) on Worker `prod-zenet-web`; all page requests hit `src/server.ts`, which does host/legacy-path 301s first.
- Business data and the Spanish legal-notice meta live in `src/content/{en,es}/*.ts` (types in `types.ts`, built by `src/lib/content.ts`). `src/i18n/*.json` is UI chrome plus, until R2 moves it, the privacy/cookies page meta.
- Single-locale page: registry `{ slugs: { es }, route }` (`route` is required only when there is no `en` slug); the `{-$locale}` layout 404s any page missing the request locale from its `staticData.page`, so routes need no per-route guard. Legal identity always comes from `legalEntity(locale)`.
- Locales: en (unprefixed) and es via `{-$locale}`. UI copy lives in `src/i18n/{en,es}.json` (`pnpm check:i18n`); legal prose lives per locale in `src/routes/{-$locale}/-legal/*.tsx`.
- Colours only through `src/styles/tokens.css` utilities (`pnpm check:colors`). Light only: no `prefers-color-scheme` variant, one `theme-color` (`THEME_COLOR`), and at most one dark `.band` per page: the close, except on `/contact`, where the band carries the form and the next steps follow it.
- Service pages: `kind: 'service'` in `page-registry.ts`; every priced page (service or landing) prices from its ladder row via `serviceOf`. The language switch goes to the page's `parent` when the target locale lacks it, else home. Prices are never stored on a page.
- Es-only landing pages (Holded pairs, Verifactu, travel agencies) have ids in `LANDING_PAGE_IDS` and a `service` ladder row (`kind: 'service'` marks the seven service pages); their copy loads per route from `src/content/es/…` and their names (breadcrumbs, related links) come from `servicesHub.landing`. Case figures live once, in `src/content/*/cases.ts` (`value: null` until the owner sets them).
- Slugs per locale and `lastmod` live in `src/lib/page-registry.ts` (router `rewrite`, internal path = `route`, defaulting to the English slug); never build public URLs from `location.pathname`.
- Agent surface: `/llms.txt`·`/es/llms.txt` and `/llms-full.txt`·`/es/llms-full.txt` are server routes under `{-$locale}`, built from `src/content` by `src/lib/llms.ts` and sent with `X-Robots-Tag: noindex`. A page's `.md` (`/index.md`, `/es.md`, `/pricing.md`…) is served by `src/server.ts` through the same converter as `Accept: text/markdown`, with a canonical `Link`. None of them go in the registry or the sitemap.
- WebMCP: `src/lib/webmcp/`. `scheduleWebMcp()` in `src/client.tsx` imports `webmcp/boot` only when `document.modelContext` (or legacy `navigator.modelContext`) exists; that waits for `load` and idle before the register chunk; schemas come from `GET /api/tools`. `book_meeting` always goes through the in-page confirm dialog. Flag `webmcp.published` (`__WEBMCP__`); optional origin-trial token `webmcp.originTrialToken`.
- Nav targets live in `src/lib/nav.ts` and are pages only: a target is `{ page }`, never a fragment (cross-page `#fragment` links are not SEO-friendly; `e2e/sitemap.e2e.ts` fails on one). `CTA_TARGET` is the single booking CTA: `/book` once `booking.published`, else the `contact` page (`/contact` · `/es/contacto`). Real pages: `contact`, `cases` (the `/case-studies` hub, with `viatsyCase` as its child), and the service pages `diagnostic` and `maintenance` (the ladder rows `diagnostic`/`maintenance`; only `growth` still lives on `/pricing`). Only agent-facing `#faq-<id>` deep links, the `#main` skip link and in-page jumps keep a fragment.
- Leads: D1 `DB` (EU) with `migrations/` (expand-only; `pnpm db:migrate:local` before preview; deploy-prod applies remote migrations before deploying). Cron `*/10` runs the email outbox; retention runs on the first tick of 03:00 UTC. Rate-limit namespaces 7301–7309 are reserved (7301 = leads). Server-only config is `__SERVER__` (read only from `src/server.ts` and `src/server/outbox.ts`); never reference it from client code. `/internal/*` is gated once by prefix in `src/server.ts` (Access JWT; 404 without config). `*.worker.test.ts` run in workerd and are typechecked by `tsconfig.workers.json` (excluded from the root config). The `@cloudflare/vitest-plugin` version must match wrangler and miniflare (`pnpm why workerd` shows one version).
- Consent and GA4: only when `site.config` `ga4Id` is set (prod `G-EEX9THLNQ9`; `null` ships no banner, button, snippet, chunk or legal variant). It is the build-time constant `__GA4_ID__`; guard every analytics path on it. Tests use `vi.stubGlobal('__GA4_ID__', …)`. Consent Mode v2 basic: `ad_*` signals are always denied, only `analytics_storage` follows the choice; the second toggle is Attribution (the 90-day first-touch for our own lead records; Google never receives it). `config` uses `send_page_view: false`; `analytics.ts` sends each `page_view` itself on load and on history navigation with `page_location` and `page_referrer` sanitised (`analyticsLocation()`/`analyticsReferrer()`: path plus `utm_*` only, no hash, cross-site referrers reduced to the origin). GA4 admin keeps history-change page views, site search and data sharing off and redaction on (docs/analytics.md section 5). Withdrawal deletes the analytics cookies through the Cookie Store API (all dot-less parent domains); ad cookies (`_gcl_*`, `_gac_*`, `FPAU`, `FPGCL`) are swept when the record changes. gtag.js loads only through the lazy `src/lib/analytics.ts` (booted by `src/client.tsx` after `load`); `src/lib/track.ts` is the only eager part; the UI is the lazy `consent-ui` chunk (copy in `src/content/{en,es}/consent.ts`), whose ResizeObserver drives `--consent-reserve`.
- Tools and booking (R9): `src/server/tools/registry.ts` is the one tool registry; HTTP `POST /api/tools/:name`, manifest `GET /api/tools`, `GET /api/health`, `GET /api/book/slots` (docs/ai-assistant.md). The page `/book` · `/es/reservar` is gated by `booking.published` in `site.config.ts` (prod `false`; also drives `CTA_TARGET`). The same flag gates the booking API (`not_configured` while false). The Google calendar secret `GOOGLE_CALENDAR` is read per request and must exist in the Secrets Store for the deploy (it holds `unconfigured` until the owner pastes the bundle); the placeholder, `UNSET`, invalid JSON or no secret all mean not configured (page shows the contact form, tools answer `unavailable`, never a 5xx). Rate-limit namespaces: leads 7301, tools 7302, book 7303, chat 7304, voice 7305. Bookings live in D1 `bookings`; the 3-a-day, buffer, per-address and email caps are enforced in one batch in `booking-store.ts`.
- Booking email confirmation (D14, migration `0006`): `book_meeting` only holds the slot for 30 min (`pending`, a `held` row with `request` and no `confirmed_at`) and emails a link `<request origin>/book?confirm=<id>.<secret>`; nothing reaches the calendar or the owner until `POST /api/book/confirm` (native form; `GET`/`HEAD` of the link never change state; Origin, `Sec-Fetch-Site`, ≤1 KB form, `BOOK_LIMITER`). Link secrets are an HMAC of the email's own id keyed with the Turnstile secret (`booking-token.ts`), stored only as SHA-256 and compared with `sameBytes` (`secret-compare.ts`): a retry carries the same link (Resend idempotency holds), a verify hash is written only after Resend accepted the email, and only a sent resend replaces the visitor's link. Both email queues share `email-queue.ts`. Booking emails (`verify`, `cancelled`) live in `booking_emails` (`booking-outbox.ts`), not `email_outbox`. Caps in `__SERVER__.booking.limits` (prod 5 per IP fingerprint a day in `booking_ip_usage`, IPv6 by /64, 3 per `email_key` in 24 h, 40 site-wide a day, both counted apart for `is_test`, 60 s resend cooldown inside the INSERT); refusals log `booking: limit { cap }`. Browser bodies carry `surface`; Turnstile actions are `book-page`/`book-chat`/`book-webmcp` and every `verifyHuman` caller passes the request hostname (exact match), with `challenge_ts` ≤ 300 s, one retry with the same `idempotency_key`, and testing keys only where `__SERVER__.turnstile.testingKeys`. Disposable domains: vendored CC0 list, `pnpm disposable:update [<commit>]`, loaded only from the booking path (CI greps `dist/client` for `mailinator`). The owner email carries `/api/book/cancel?t=…` (GET page, POST deletes with `sendUpdates=all`). The 03:00 tick runs `purgeCalendarEvents` (24 months, `sendUpdates=none`, per-row skips, least recently tried first) before `purgeExpired`, which keeps a lead while its event exists up to a 760-day backstop (logged). Conversions fire once on the confirmed view (`outcome=booked`). Booking tokens appear in request URLs, so Workers Logs hold them (RUNBOOK 11). The confirm and cancel pages send `Referrer-Policy: same-origin` (not `no-referrer`: that makes browsers post `Origin: null`).
- Assistant (R10): `POST /api/chat` (AI SDK 7 + `workers-ai-provider`, both pinned; `docs/ai-assistant.md`). Gated by `assistant.published` in `site.config.ts` (prod `false`; build-time `__ASSISTANT__`). Binding `AI` only in `env.production`; local and CI use the scripted model via `__CHAT_FAKE__` (the production build must not contain `FAKE_ASSISTANT_SENTINEL`; CI greps). Workers AI is never called in CI. History is server-held in D1 (`chat_sessions`, `chat_messages`, `ai_usage`, migration `0003`); unlinked transcripts are purged after 30 days by the existing cron. Chat bookings go through `book_meeting` (the model only proposes; the card books). `CHAT_LIMITER` = namespace 7304. The launcher is the only chat code in the entry graph; the panel, the AI client and the copy load on interaction.
- Voice (R12): `POST /api/voice/session` mints an ElevenLabs conversation token after Turnstile `voice` (D1 `voice_sessions`, 30 a day, 5-minute calls); one agent per locale, config as code in `elevenlabs/voice-agents.generated.json` (`pnpm voice:plan|apply`, `docs/ai-assistant.md` "Voice"). ElevenLabs calls `/api/tools/*` with the bearer secret plus `X-Voice-Session`, and the session sets locale, zone and test flag. Gated by `voice.published` (prod `false`; build-time `__VOICE__`) and per-locale `voice.agents` ids (`null` until `pnpm voice:apply`); `__VOICE_FAKE__` swaps in the scripted SDK locally (the production build must not contain `FAKE_VOICE_SENTINEL`). `VOICE_LIMITER` = namespace 7305 (the next free one is 7306); secret `ZENETLABS_PROD_ELEVENLABS_API_KEY` (binding `ELEVENLABS_API_KEY`). The page carries only `voice-entry.ts` and the callouts on home and contact (on contact it sits below the form so its post-hydration appearance shifts nothing in view); the panel mounts in its own root and the SDK loads when it opens. `Permissions-Policy` has `microphone=(self)` only when `__VOICE__` is on. `pnpm voice:plan` checks the agents' model against ElevenLabs' list.
- Design system "The front desk" (`src/styles/tokens.css`; vault `design-system.md`): white ground, `bg-tint` (#f2f5f4) for alternating regions, green-black ink. Primary buttons are ink (`cta`), secondary outlined ink; desk green `agent` is the brand colour and owns the agent (the chat launcher, the voice call `.voice-door`, `-soft` fills, focus, links); amber `human` marks a person only; blue `tool` marks the customer's tools only. `.band` (the dark desk-green band, the close on every page but `/contact`) and `.scope-page` (restores the page tokens, for a form card or dialog inside a band) are the only scopes; `BAND_CARD` is the `.scope-page` card (contact form, `/book`) on a band, with `shadow-band`. ## Gotchas
- Content, price, registry or prompt changes change the voice agents: regenerate with `VITEST_MAX_WORKERS=2 pnpm exec vitest run src/server/voice/agent-config.test.ts -u` and commit the JSON (CI fails on drift). Voice e2e uses the fake SDK; the real one and ElevenLabs are never in CI. The voice privacy text renders only when `voice.published`, so `CONSENT_VERSION`, the privacy `updated` dates and `lastmod` bump in the flip PR.
- After changing `src/server/chat/prompt.ts`, `knowledge.ts` or the content it reads, re-run the manual question set against a preview alias (docs/ai-assistant.md "Activation"). Bump `CONSENT_VERSION`, the privacy `updated` dates and `PAGES.privacy.lastmod` together with any privacy page change; the assistant's privacy section renders only when `assistant.published`, so those bumps belong to the flip PR.
- Slot labels are hand-formatted (`src/lib/slot-format.ts`); never render `Intl` output. Temporal is `undefined` in workerd. `/book` reads `?tz` with `validateSearch: (raw) => raw` (an unknown zone must not redirect).
- e2e clears local bookings at preview start (`pnpm db:clear-bookings:local`). On a fresh box run `node scripts/local-calendar-secret.mjs <store-id>` once. Don't hold booking tests on a slot near the 12 h notice edge.
- Calculator: `calculator.published` in `site.config.ts` gates the route (404), sitemap, llms, `.md` and in-site links; production stays `false` until the owner reviews `src/content/pricing-rules.ts`. Bump its `version` on every edit; `src/lib/estimate.test.ts` must stay green. The no-JS GET form must round-trip TanStack's search serializer or SSR answers 307 (`calculator-answers.test.ts`). Its lead goes through the contact form (source `form`), not a separate lead contract. Its legal sentences (`CalculatorUse` in `privacy-extras-*.tsx`, the estimate line in the aviso legal) already exist behind the build-time constant `__CALCULATOR__` (`SITE` can't be constant-folded; keep the vite and vitest defines and `env.d.ts` in sync), so the flip PR only bumps `CONSENT_VERSION`, the privacy and aviso legal `updated` dates and their `lastmod`.
- CI step "Analytics loads only lazily" (`build-prod`): `googletagmanager` must appear in `dist/client` and only in `assets/analytics-*`, and no chunk except `consent-ui-*` may import `./analytics-` statically. Smoke expects `'consent','default'` in the HTML of `/` and `/es` and keeps "no Google tag" (the SSR HTML never carries the tag before consent). To switch GA4 off, set `ga4Id: null` and revert both (`docs/RUNBOOK.md` section 9).
- e2e seeds a rejected consent via `storageState` (`e2e/consent-seed.ts`); `e2e/consent.e2e.ts` clears it. Bump `COOKIE_CONSENT_REVISION` when cookies or vendors change. Activation checklist: `docs/analytics.md`.
- Bump `CONSENT_VERSION` (`src/server/lead-fields.ts`) when the consent sentence or a privacy page changes. e2e needs `scripts/fake-services.mjs` on :4175 (Playwright starts it).
- A route file `x.tsx` next to a folder `x/` is that folder's layout; pages that render on their own go in `x/index.tsx` plus siblings (see `services/integrations/`).
- Verifactu dates live only in `src/content/es/verifactu.ts`. Re-check the BOE and the AEAT before each deploy; when anything changes, update the module, `checkedOn` and the `verifactu` lastmod. Never write "certificado" or "VERI*FACTU" in copy.
- Page-body copy (`home`, `pricing`, `about`, `cases`, `cases-hub`, `contact`, `companies`, service pages, the services hub, the landing pages and the Viatsy case page) is imported only from its route component or server-only code, never from chrome, `head()`, `scripts()`, `pages.ts` or `content.ts`. `e2e/js-budget.e2e.ts` enforces it. Service-page and hub copy loads only through `src/content/load.ts`: by dynamic import from route loaders and from `serviceBodies` in `src/lib/llms.ts`. The leak guard is the js-budget sentinels.
- A new page-content module must be added to `buildLlmsFull` and `llms.test.ts`. The `.md` URL, the head link and the llms `Pages` line come from the registry.
- Bump a page's `lastmod` when its main content, JSON-LD or links change.
- JSON-LD and inline scripts go in route `scripts()`, never `head()` (React #418). Theme-color pair lives in RootDocument.
- No Date.now()/new Date() in render. Tailwind 4: `outline-hidden`, not `outline-none`.
- workers-types shadows Element.append — use appendChild.
- Playwright: wait for `body[data-hydrated="true"]` before clicking.
- The default Playwright project must stay without `modelContext`; the `chromium-webmcp` project runs `webmcp-real.e2e.ts` with `--enable-blink-features=WebMCP`. A WebMCP `execute` never throws: return the tool envelope.
- `pnpm e2e` serves whatever is in `dist/` and reuses any server already on :4173: after a `CLOUDFLARE_ENV=production pnpm build`, run `pnpm build` again and stop stale previews first (the real Turnstile key fails locally).
- A missing input is `null` plus `// TODO(albert)`, never a placeholder string. The placeholder test greps the rendered site.
- `pnpm-workspace.yaml` pins `undici` for `@ai-sdk/provider-utils` (the `ai` package pulls a version CI's `pnpm audit --prod --audit-level=high` rejects); re-check it when bumping `ai`. After any version bump run `pnpm dedupe`. wrangler can exit 0 without deploying — the deploy action greps for confirmation.
